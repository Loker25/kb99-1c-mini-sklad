# Мини-Склад

Учебный проект на платформе **1С:Предприятие 8.3**, разработанный в рамках обучения в компании КБ99.

Проект предназначен для изучения разработки конфигураций 1С, автоматизации складского учёта, работы с документами, регистрами накопления и сведений, механизмами учёта партий, отчётами, печатными формами и системой контроля версий Git.

## Назначение проекта

«Мини-Склад» - учебная конфигурация для автоматизации основных операций складского учёта:

- оформления поступления и реализации товаров;
- учёта остатков товаров по складам;
- хранения информации о партиях и их характеристиках;
- расчёта стоимости поступивших и реализованных товаров;
- списания товаров по методу FIFO;
- формирования отчётов и печатных форм.

## Состав конфигурации

### Справочники

- **Товары** - хранение сведений о товарах.
- **Контрагенты** - хранение информации о поставщиках и покупателях.
- **Склады** - хранение информации о местах хранения товаров.
- **ВариантыТоваров** - хранение наборов свойств, используемых для идентификации партий товаров.
- **ДополнительныеСвойстваТоваров** - хранение дополнительных свойств объектов.

### План видов характеристик

- **СвойстваТоваров** - описание дополнительных характеристик товаров и партий, в том числе даты поступления.

### Документы

- **ПоступлениеТоваров** - оформление поступления товаров на склад и формирование приходных движений.
- **РеализацияТоваров** - оформление продажи товаров, проверка доступных остатков и формирование расходных движений.

В документах используется табличная часть `Товары` с реквизитами:

- `Товар`;
- `Количество`;
- `Цена`;
- `Сумма`.

Сумма строки рассчитывается автоматически при изменении количества или цены.

Для табличной части предусмотрена проверка заполнения. В документе реализации также выполняется проверка положительности количества товаров.

### Регистры накопления

- **ОстаткиТоваров** - учёт количества товаров на складах, приходов, расходов и текущих остатков.
- **СтоимостьТоваров** - учёт стоимости товарных партий и остаточной стоимости после списания.
- **Продажи** - учёт количества реализованных товаров, выручки и себестоимости продаж в разрезе товаров и контрагентов.

### Регистры сведений

- **ЗначенияСвойствТоваров** - хранение значений характеристик наборов свойств товаров, используемых при идентификации и учёте партий.

### Общие модули

- **РаботаСДокументами** - общая логика расчёта суммы строк табличной части документов.
- **РаботаСоСправочниками** - получение актуальной цены товара из регистра сведений

## Списание партий по FIFO

В документе `РеализацияТоваров` реализован механизм списания товаров по методу FIFO.

При проведении документа система:

1. Получает доступные остатки товаров и их стоимость.
2. Определяет партии по дате поступления.
3. Распределяет требуемое количество товара между партиями в порядке их поступления.
4. Рассчитывает себестоимость списания с учётом остаточной стоимости каждой партии.
5. Формирует расходные движения по регистрам `ОстаткиТоваров` и `СтоимостьТоваров`.
6. Записывает количество, выручку и себестоимость реализации в регистр `Продажи`.

При частичном списании партии её остаточная стоимость рассчитывается пропорционально списанному количеству.

Перед проведением реализации выполняются проверки количества товаров и наличия необходимых данных о партиях, включая дату поступления.

## Отчёты и печатные формы

### Отчёт «ОборотыПоТоварам»

Отчёт построен с использованием системы компоновки данных (СКД) и виртуальной таблицы `ОстаткиТоваров.ОстаткиИОбороты`.

Позволяет анализировать складские операции за выбранный период: начальные остатки, поступления, расходы и конечные остатки товаров.

### Отчёт «ОстаткиТоваров»

Отчёт предназначен для просмотра остатков товаров на складах. Позволяет получить информацию о количестве товаров, доступных на выбранную дату, и проанализировать складские остатки.

### Печатная форма реализации

Для документа `РеализацияТоваров` предусмотрены команда `Печать` и макет печатной формы.

Печатная форма содержит основные реквизиты документа, перечень товаров, количество, цену, суммы по строкам и общую сумму документа.

## Структура репозитория

- `Неделя1/` - выгрузка конфигурации, созданная в рамках первой недели практики.
- `Неделя 2/` - версия конфигурации с доработками второй недели.
- `Неделя 3/` - актуальная выгрузка конфигурации с механизмом учёта партий и списания по FIFO.
- `README.md` - описание проекта и инструкция по загрузке конфигурации.
- `.gitignore` - правила исключения файлов, которые не следует добавлять в Git.

В последней версии проекта следует использовать каталог `Неделя 3`.

## Загрузка конфигурации

Для загрузки конфигурации из репозитория:

1. Склонировать репозиторий или скачать архив с GitHub.
2. Создать новую пустую информационную базу 1С.
3. Открыть информационную базу в режиме «Конфигуратор».
4. Выбрать **Конфигурация → Загрузить конфигурацию из файлов**.
5. Указать каталог `Неделя 3`.
6. Дождаться завершения загрузки и сохранить конфигурацию.
7. Выполнить обновление конфигурации базы данных.
8. Запустить информационную базу в режиме «1С:Предприятие».

## Проверка работы

Для проверки основных возможностей конфигурации рекомендуется:

- создать и провести документ поступления товаров;
- проверить приходные движения и остатки;
- создать документ реализации;
- проверить списание товаров из нескольких партий по FIFO;
- проверить частичное и полное списание партий;
- проверить остаточную стоимость партий;
- проверить движения в регистрах `ОстаткиТоваров`, `СтоимостьТоваров` и `Продажи`;
- сформировать отчёт «ОборотыПоТоварам»;
- проверить печатную форму документа реализации.
